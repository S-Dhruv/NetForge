12Nov - worker/worker.go now contains a `Handler` function which has the main job to be executed (nil for now), this implements the Strategy pattern which gives the caller the chance to decide what job to do and how, a `Store` interface which has its own UpdateState. The reason `Store` interface exists is because we want to give the worker the ability to only call UpdateState and not all the methods mentioned the other interface, implementing a Interface Segregation Principle (a caller only depends on the methods it actually uses). In the test, we create 5 jobs then update their state to running before sending them through the channel, we call `RunWorkers` which creates `n` of workers for the jobs. The test pushes the job through a buffered channel and closes it, the `RunWorkers` creates go routines for each worker and run a loop for each job in the channel and addresses them individually, adding WaitGroups, Done, Wait methods to synchronize all the jobs. Also, the `RunWorkers` handles valid transition state and error classification using mutex locks since we are working with parallel go routines. Instead of pausing the run, we accumilate the errors in an array which is return at the end of the function call.

# NetForge — session continuity

Read `docs/agent-memory.md` first whenever starting or resuming work. It contains
the project summary, teaching contract, current implementation, known gaps, and
next task. Inspect the relevant code and `git status --short` before acting;
read additional docs only when the task needs them or the summary is stale.

Keep `docs/agent-memory.md` current after meaningful progress and before handing
work back: record changed behavior, decisions, actual verification outcomes,
remaining gaps, and the next small task. Update the relevant existing tracking
docs as described there. Never report unexecuted tests as passing.

This is a learning project. Default to teaching and reviewing; do not create or
overwrite Go implementation files unless the user explicitly requests it.
Stage 0 means goals, constraints, concepts, and one small task, without code or
prescribed field/schema lists. Give full solutions only when explicitly asked.
Explain unfamiliar technical terms immediately in brackets in learner replies.
Preserve existing user changes and never put secrets in project memory.
